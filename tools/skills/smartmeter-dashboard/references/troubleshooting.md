# スマートメーター表示のトラブルシューティング

## スマートメーターが見つからない

- スマートメーターは通常、Wi-SUN (B ルート) で HEMS コントローラやゲートウェイとつながっていて、LAN 上にはそのゲートウェイ経由で現れる。B ルートの利用申請やゲートウェイの設定が済んでいるかユーザーに確認してもらう。
- 他の機器は見つかるのに `0288` で始まる EOJ だけがない場合は、ゲートウェイがスマートメーターを LAN に公開していない可能性が高い。
- 何も見つからない場合は `discover_devices` の `timeout_sec` を長く (例: 10) して一度だけ探索し直す。それでも見つからなければ、次を確認するようユーザーに伝える。
  - el-mcp-server と機器が同じサブネットにあるか
  - **`bind: address already in use`**: 同じホストで UDP 3610 番ポートを使うプロセス (ECHONET Lite エミュレータなど) が動いていないか
  - **Windows**: Windows Defender ファイアウォールで UDP 3610 の通信を許可しているか
  - el-mcp-server は IPv4 のみ対応。IPv6 でしか応答しない機器は探索できない

## 履歴が読めない (history_error)

- スマートメーターは B ルート越しの応答が遅く、30 分毎の履歴の読み出しがタイムアウトすることがある。少しおいて一度だけ `render_smartmeter_ui` を呼び直す。
- 要求した日と違う日の履歴が返った、というエラーは、別の HEMS コントローラが同時に積算履歴収集日 (EPC `E5`) を書き換えた場合などに起きる。少しおいて一度だけ呼び直し、それでも同じならそのままユーザーに伝える。
- 履歴の一部の時間帯だけ値がないのは、メーターがその時間帯のデータを持っていない (未来の時間帯、計測前など) ため。エラーではない。

## 現在の値も読めない

- タイムアウトする場合は、ゲートウェイやメーターの IP アドレスが変わった可能性がある。`discover_devices` で探索し直して IP と EOJ を確認する。
