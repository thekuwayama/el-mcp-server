# smartmeter-dashboard

el-mcp-server のツールでスマートメーターを探し、ダッシュボードを表示するための手順です。

## 1. スマートメーターを探索する

- `discover_devices` を呼ぶ。結果は IP アドレスごとの EOJ の一覧になっている。
- EOJ が `0288` で始まるもの (例: `028801`) がスマートメーター。その IP と EOJ を控える。
- ユーザーが IP と EOJ を既に示している場合は探索を省略してよい。

## 2. 対象を決める

- 1 台だけ見つかったら、それを使う。
- 複数見つかったら、IP と EOJ を並べてどれを表示するかユーザーに確認する。勝手に選ばない。
- 見つからなかったら `references/troubleshooting.md` を読み、探索し直すかユーザーに状況を伝える。

## 3. ダッシュボードを表示する

- `render_smartmeter_ui` を ip と eoj を指定して呼ぶ。
- ユーザーが日付を指定した場合 (「昨日」「先週の月曜」など) は、日本時間 (JST) の今日を基準に YYYY-MM-DD に直して date に渡す。指定できるのは今日から 99 日前まで。範囲外ならユーザーにそう伝える。日付の指定がなければ date は省略する (今日になる)。
- ダッシュボードの前日/翌日ボタンは AI を介さずに表示日を切り替える。別の日を見たいと言われても、ボタンで切り替えられることを伝えれば足りる。AI から呼び直すのは、ユーザーが特定の日付を指示した場合だけでよい。
- このツールは履歴の読み出しのために積算履歴収集日 (EPC `E5`) を書き換え、取得後に元の値へ戻す。AI から `set_property` で何かを書き込む必要はない。

## 4. 結果を伝える

- MCP Apps 対応クライアントではダッシュボードが表示される。表示したことを一言伝え、ユーザーの質問 (例: 「今どれくらい使っている?」) があればその値だけ答える。ダッシュボードの内容を全部書き写さない。
- MCP Apps 非対応のクライアント (Claude Code CLI など) では JSON が返る。次を要約して伝える。
  - 稼働状態、瞬時電力 (W)、瞬時電流 (R 相/T 相、A)、積算電力量 (kWh)
  - 表示した日付と、その日の買電/売電の合計 (kWh)
  - 買電が最も多かった 30 分の時間帯
- JSON に履歴のエラー (history_error) があれば、その日の履歴は読めなかったと伝え、`references/troubleshooting.md` を参照する。現在の値だけは読めていることが多いので、そちらは伝える。
