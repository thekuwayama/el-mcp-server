# 機器操作のトラブルシューティング

## SetC_SNA が返った

機器が書き込みを拒否したことを示す。次の順に切り分ける。

1. **Set できない EPC**: `get_epc_detail` のアクセス規則に Set がない。仕様上書き込めないので、ユーザーにそう伝える。
2. **バイト数が違う**: `get_epc_detail` のデータ型が示すバイト数と EDT の長さが一致しているか確認する。1 バイトの値を `0041` のように 2 バイトで送ると拒否される。
3. **範囲外・未定義の値**: 数値は範囲内か、列挙値は定義済みの値か確認する。
4. **機器固有の制約**: 仕様上は Set できても、機器が対応していない値や、今の運転状態では受け付けない値がある (例: 停止中は運転モードを変えられない機種、自動運転中は設定温度を受け付けない機種)。`get_property` で稼働状態 (EPC `80`) などを確認し、制約がありそうならユーザーに伝える。

## EDT の書き方

- EDT は 16 進文字列で渡す。`26` は 10 進の 26 ではなく 0x26 (= 38) になる。10 進の値は必ず 16 進に変換する (26 → `1A`)。
- 複数バイトの数値はビッグエンディアン (上位バイトが先)。
- 符号付きの型は 2 の補数 (1 バイトの -1 は `FF`)。
- 稼働状態 (EPC `80`) は ON が `30`、OFF が `31`。`01` / `00` ではない。
- 多くの列挙値は `41` から始まる (例: 運転モード)。`01` から始まると思い込まず、`get_epc_detail` の列挙値を使う。
- 単位に倍率がある EPC (0.1 ℃ 単位、10 W 単位など) があるので、`get_epc_detail` の単位・倍率を見て変換する。

## 応答がない・通信できない

- **`bind: address already in use`**: 同じホストで UDP 3610 番ポートを使うプロセス (ECHONET Lite エミュレータなど) が動いている。そのプロセスを止めるか、別ホストで動かすようユーザーに伝える。
- **タイムアウト**: 機器が別のサブネットにある、電源が切れている、IP アドレスが変わった、のいずれかが多い。`discover_devices` で探索し直して IP と EOJ を確認する。見つからない場合は `timeout_sec` を長くして再探索する。
- **IPv6 の機器**: el-mcp-server は IPv4 のみ対応。IPv6 でしか応答しない機器は操作できない。
- **Windows**: 初回起動時に Windows Defender ファイアウォールで UDP 3610 の通信を許可していないと探索・通信できない。

## 値は書けたが状態が変わらない

- Set_Res は「受け付けた」ことを示すだけで、即座に反映されるとは限らない。数秒おいて読み直す。
- 機器によっては、別の EPC (稼働状態など) の条件を満たさないと設定値が実際の動作に反映されない。
