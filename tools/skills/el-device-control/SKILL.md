# el-device-control

el-mcp-server のツールで ECHONET Lite 機器を操作するための手順です。`set_property` は実機の状態を変えるため、次の順序を守ってください。

## 1. 対象機器を特定する

- IP アドレスと EOJ が分かっていなければ `discover_devices` で探索する。
- 同じクラスの機器が複数見つかった場合は、どれを操作するかユーザーに確認する。勝手に選ばない。
- 機器クラス名だけ分かっていて EOJ が分からない場合は `search_device_class` でクラスコード (4 桁) を調べる。

## 2. ダッシュボードがある機器はダッシュボードを表示する

EOJ のクラスコード (先頭 4 桁) が次の表にあれば、対応する `render_*_ui` を呼んでダッシュボードを表示する。

| クラス | 機器 | ダッシュボード | ダッシュボードから操作できる項目 |
|---|---|---|---|
| `0130` | 家庭用エアコン | `render_aircon_ui` | 稼働状態・運転モード・設定温度・風量 |
| `027D` | 蓄電池 | `render_battery_ui` | 稼働状態・運転モード |
| `027E` | 電気自動車充放電器 (V2H) | `render_v2h_ui` | 稼働状態・運転モード |
| `0279` | 住宅用太陽光発電 | `render_solar_ui` | なし (表示のみ) |
| `0288` | 低圧スマート電力量メータ | `render_smartmeter_ui` | 前日/翌日の切り替え (`date` で日付指定、省略時は今日) |

- ダッシュボードで操作できる項目の変更は、ダッシュボードから操作してもらう。ダッシュボードの操作は AI を介さずに `set_property` と再表示まで行われるので、AI から `set_property` を呼ぶ必要はない。ここで終わる。
- 次の場合だけ手順 3 以降に進む。
  - 表にないクラス
  - 変更したい EPC がダッシュボードで操作できない項目
  - クライアントが MCP Apps 非対応で、`render_*_ui` がダッシュボードではなく JSON を返した (Claude Code CLI など)。この場合は JSON の内容を要約して現在の状態を伝える。
- 表にないクラスは、`get_property` で変更予定の EPC の現在値を取得してユーザーに伝える。

## 3. 書き込む値を仕様で確認する

- `get_epc_detail` で対象 EPC を調べ、次を確認する。
  - アクセス規則に Set があること (Set がなければ書き込めない。ユーザーにそう伝えて終わる)
  - データ型・バイト数・値の範囲・列挙値
- ユーザーの言葉 (例: 「冷房」「26 度」) を EDT (hex) に変換する。変換は `get_epc_detail` の列挙値・範囲に基づいて行い、記憶に頼らない。
- 変換に迷う点があれば `references/troubleshooting.md` を読む。

## 4. 変更する

- 書き込む内容 (機器・EPC・現在値 → 新しい値) をユーザーに示してから `set_property` を呼ぶ。
- elicitation に対応したクライアントでは `set_property` 自体が確認フォームを出す。ユーザーが拒否した場合は再試行しない。
- 一度に変えるのはユーザーが頼んだ EPC だけにする。関連しそうな項目を勝手に変えない。
- `SetC_SNA` が返ったら `references/troubleshooting.md` で原因を切り分ける。同じ値で何度も再送しない。

## 5. 反映を確認する

- ダッシュボードがあるクラスなら、同じ `render_*_ui` をもう一度呼んで変更後の状態を見せる。
- それ以外は `get_property` で同じ EPC を読み直し、書き込んだ値になっているか確認する。
- Set_Res が返っても機器の内部状態の切り替えに時間がかかることがある。値が変わっていなければ数秒おいて一度だけ読み直し、それでも違えば結果をそのままユーザーに伝える。
